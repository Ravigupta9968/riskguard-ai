## 2. Snowflake Data Model

**Database**: `RISKGUARD_DB`  
**Schemas**: `CORE` (transactional data), `ANALYTICS` (derived/scored), `RAG` (regulatory docs), `APP` (app config)

### CORE Schema

| Table | Purpose | Key Columns |
|---|---|---|
| `CUSTOMERS` | Customer master | customer_id, name, type (INDIVIDUAL/BUSINESS), country, risk_rating, onboarding_date, pep_flag, sanctions_flag |
| `ACCOUNTS` | Bank accounts | account_id, customer_id, account_type, currency, opened_date, status |
| `TRANSACTIONS` | Transaction ledger | txn_id, account_id, txn_date, amount, currency, counterparty, channel, country, txn_type, description |
| `WATCHLIST_ENTRIES` | Sanctions/PEP list | entry_id, list_name, entity_name, entity_type, country, match_score |

### ANALYTICS Schema

| Table | Purpose | Key Columns |
|---|---|---|
| `RISK_SCORES` | ML-style risk scores per customer | customer_id, score_date, risk_score (0-100), risk_category, contributing_factors (VARIANT) |
| `FRAUD_ALERTS` | Generated alerts | alert_id, customer_id, txn_id, alert_type, severity, status (OPEN/INVESTIGATING/CLOSED), created_at, rule_id |
| `ALERT_RULES` | Detection rule catalog | rule_id, rule_name, description, category, threshold_json (VARIANT), is_active |
| `INVESTIGATIONS` | Case management | investigation_id, alert_id, customer_id, assigned_to, status, priority, opened_at, closed_at, summary, finding |
| `SAR_REPORTS` | Suspicious Activity Reports | sar_id, investigation_id, filing_date, narrative, status, generated_by |

### RAG Schema

| Table | Purpose | Key Columns |
|---|---|---|
| `REGULATORY_DOCS` | BSA/AML policy chunks | doc_id, source_doc, section_title, chunk_text, category, effective_date |

### APP Schema

| Table | Purpose |
|---|---|
| `AUDIT_LOG` | All AI-generated actions/summaries logged for compliance |

## 3. Synthetic Data Plan

All data generated via SQL `INSERT` using `UNIFORM()`, `RANDSTR()`, `UUID_STRING()`, arrays, and `DATEADD()`:

| Table | Volume | Strategy |
|---|---|---|
| CUSTOMERS | ~500 | Mix of clean + high-risk profiles (10% PEP, 5% sanctioned, 20% high-risk countries) |
| ACCOUNTS | ~800 | 1-3 accounts per customer |
| TRANSACTIONS | ~50,000 | 90 days of activity. ~5% suspicious patterns: structuring (<$10K splits), round-tripping, rapid velocity, high-risk corridors |
| WATCHLIST_ENTRIES | ~100 | Fuzzy matches against ~20 customer names |
| RISK_SCORES | ~500 | One per customer, scores correlate with suspicious patterns |
| FRAUD_ALERTS | ~200 | Triggered by rules against suspicious transaction patterns |
| ALERT_RULES | ~15 | Realistic AML rules: structuring, velocity, jurisdiction, dormant account, etc. |
| INVESTIGATIONS | ~50 | Subset of alerts escalated to cases |
| SAR_REPORTS | ~10 | Completed investigations with AI-generated narratives |
| REGULATORY_DOCS | ~200 chunks | FinCEN BSA/AML manual sections, FATF recommendations, bank policy text (synthetic but realistic) |

**Suspicious patterns embedded in data:**
- "Structuring": Multiple deposits just under $10,000 within 48 hours
- "Round-tripping": Money sent to Entity A → returned from Entity B (same beneficial owner)
- "Velocity spike": 10x normal transaction volume in a 7-day window
- "High-risk corridor": Transactions to/from sanctioned jurisdictions
- "Dormant activation": Accounts inactive for 6+ months suddenly active with large flows

## 4. Cortex Components

| Component | Purpose | Implementation |
|---|---|---|
| **CORTEX.COMPLETE** | Generate investigation summaries, explain risk factors, produce SAR narratives, answer freeform questions | Called via SQL or Agent tool; model: `mistral-large2` or `llama3.1-70b` |
| **CORTEX.SENTIMENT** | Gauge tone of transaction descriptions / notes | Used in risk scoring pipeline |
| **Semantic View** | Structured Cortex Analyst interface over CORE + ANALYTICS | YAML model mapping natural language to SQL against the data model |
| **Cortex Search Service** | RAG over regulatory documents | Index on `REGULATORY_DOCS.chunk_text` with `section_title` + `category` as filterable attributes |
| **Cortex Agent** | Orchestrator combining Analyst (SQL) + Search (RAG) + Complete (reasoning) | The central intelligence layer the Streamlit app calls |

## 5. Agent Architecture

**Single Cortex Agent** named `RISKGUARD_AGENT` with three tool integrations:

```
RISKGUARD_AGENT
├── Tool 1: Cortex Analyst (Semantic View)
│   → Converts NL questions into SQL over transaction/alert/customer data
│   → "Show me all high-risk customers with >$50K in transactions this month"
│
├── Tool 2: Cortex Search (Regulatory RAG)
│   → Retrieves relevant BSA/AML regulatory text
│   → "What are the reporting thresholds for CTR filings?"
│
└── Tool 3: Cortex Complete (via data_to_text / analyst handoff)
    → Generates explanations, summaries, SAR narratives
    → "Explain why customer C-0042 was flagged"
```

The Agent decides which tool(s) to invoke based on the user's question, combines results, and returns a coherent answer.

## 6. Regulatory RAG Architecture

```
REGULATORY_DOCS table (200 chunks)
    │
    ▼
Cortex Search Service ("riskguard_regulatory_search")
    - search_column: chunk_text
    - attributes: source_doc, section_title, category
    - embedding_model: snowflake-arctic-embed-l-v2.0
    │
    ▼
Agent Tool: search_regulatory_docs
    - User asks policy question → Agent calls Search
    - Top-K chunks returned → Agent synthesizes answer with citations
```

**Document categories**: BSA/AML Requirements, CTR/SAR Filing Rules, Customer Due Diligence (CDD), Enhanced Due Diligence (EDD), FATF Recommendations, Sanctions Compliance, PEP Screening.

## 8. Main User Workflows

### Workflow A: "Triage New Alerts"
1. Analyst opens Dashboard → sees 12 new HIGH severity alerts
2. Clicks an alert → Investigation Panel shows customer profile + transaction history
3. Clicks "Explain Risk" → Agent returns: "Customer C-0042 flagged for structuring: 7 cash deposits of $9,500-$9,900 within 48 hours, totaling $68,300"
4. Reviews evidence, marks alert as "Investigating"

### Workflow B: "Investigate a Customer"
1. Analyst selects customer from high-risk list
2. Sees full transaction timeline, risk score history, watchlist matches
3. Asks Agent: "What is this customer's transaction pattern over the last 90 days?"
4. Agent runs SQL via Analyst → returns summary with charts
5. Asks: "What are the SAR filing requirements for structuring?"
6. Agent searches regulatory docs → returns BSA/AML guidance with citations

### Workflow C: "Generate SAR Narrative"
1. After investigation, analyst clicks "Draft SAR Narrative"
2. Agent compiles: customer profile + suspicious transactions + rule triggers + regulatory context
3. Generates audit-ready narrative with all required SAR fields
4. Analyst reviews, edits if needed, marks as filed

### Workflow D: "Ad-hoc Analysis"
1. Analyst asks: "Which customers sent more than $100K to high-risk countries this quarter?"
2. Agent converts to SQL → runs → returns results table + explanation
3. Follow-up: "Show me the transaction details for the top result"
